# Milestone 02: True Prefix Lookups & Two-Endpoint Read Protocol

**Status**: 🚧 **In Progress**  
**Target Completion**: 2026-W42  
**Epic**: Upgrade `filippo.io/torchwood/mpt` to variable-length canonical keys (`<= 1024` bytes) with verifiable prefix subtree discovery, decouple MPT state commitment queries (`/vindex/v1/keys/`) from lock-free Pebble mini-log pagination (`/vindex/v1/entries/`), move domain eTLD+1 Public Suffix List enforcement to the HTTP read server, and switch CT/MTC mappers to single reversed-label trailing-dot domain keys per [`PREFIX_LOOKUPS.md`](../PREFIX_LOOKUPS.md).

---

## 1. Objectives & Success Criteria
1. **Variable-Length MPT Keys & Hybrid Storage Keying (`1.1.0`)**: Upgrade `filippo.io/torchwood` to `v0.10.1+` (`[]byte` MPT keys `1..1024` bytes, printable NUL-free ASCII `0x21..0x7E`), retain fixed 32-byte `SHA256(key)` keys inside Pebble (`'c' + 32B KeyHash + 8B ^chunkNum`) and active chunk caches, and expose point (`ProveKey`/`VerifyKey`) and prefix (`ProvePrefix`/`VerifyPrefix`) proof primitives in `internal/tree`.
2. **Two Orthogonal Read Endpoints (`1.1.0`, `1.1.1`)**: Replace `/vindex/v1/lookup/{keyhash}` with `GET /vindex/v1/keys/{key...}[?prefix=true]` (MPT + Output Log only) and `GET /vindex/v1/entries/{key...}?before=X[&limit=Y]` (Pebble only, zero MPT locks), with server-side eTLD+1 Public Suffix List policy checks and `maxPrefixKeys` cardinality caps on prefix scans.
3. **End-to-End Client & Pagination Soundness (`2.6.1`, `2.6.2`, `2.6.3`)**: Enforce two-sided prefix proof verification (`HasPrefix` + strict ascending `Key.Compare` order + `TreeHash` + `VerifyPrefix`), authenticate every page of `/vindex/v1/entries/` against `subRoot` (Page 1) or the preceding page's prefix compact range root (Pages 2+), reject truncated/omitted pages and overflow indices, and remove legacy unverified JSON/SHA-256 fallbacks.
4. **Reversed-Label Trailing-Dot Mappers & Ecosystem Fixes (`1.1.0`, `2.2.3`)**: Emit 1 reversed-label domain key with a mandatory trailing dot per SAN/CN (`mail.google.com` -> `com.google.mail.`, `*.google.com` -> `com.google.*.`) in CT and MTC without guest-side PSL suffix expansion, enforce IDNA Punycode conversion, extract Subject CN in MTC without 64-span truncation, remove CT plaintext fallback, and canonicalize SumDB module paths via `module.EscapePath`.
5. **Benchmark-Verified Performance Commits**: Include dedicated unit tests and `testing.B` (`b.Loop()`, `-benchmem`) benchmarks for MPT variable-length key operations, lock-free `/entries/` serving vs `/keys/`, and CT/MTC per-bundle mapping throughput, citing before/after scores in commit messages.
